# UI 동기화 점검 체크리스트

## 문서 목적

이 문서는 Core 패키지에서 **HUD, 윈도우, 아이콘, 플로팅 텍스트, 팝업, 시스템 메시지**가
현재 런타임 상태와 맞지 않게 보일 때 확인할 항목을 정리한 체크리스트입니다.

Core의 UI는 단순 표시 레이어가 아니라,
캐릭터 상태, 저장 복원, 윈도우 생명주기, 프레젠터/컨트롤러, Addressables 프리팹 로드와 연결됩니다.
그래서 UI 문제가 생겼을 때는 “프리팹이 잘못됐다”보다
**데이터 소스, 구독 시점, 첫 sync 시점, 풀링/재사용 상태**를 먼저 보는 것이 좋습니다.

---

## 먼저 확인할 관련 클래스 / 폴더

- `UI/Core/Base/UIWindowManager.cs`
- `UI/Core/Base/UIWindow.cs`
- `Characters/Player/PlayerUIController.cs`
- `UI/Core/FloatingText/UIFloatingTextManager.cs`
- `Popup/PopupManager.cs`
- `SystemMessage/SystemMessageManager.cs`
- 관련 Presenter / HUD / Window / Icon 계층

---

## 이런 증상에서 먼저 봅니다

- 값은 바뀌었는데 HUD가 갱신되지 않는다
- 윈도우를 다시 열면 이전 상태가 남아 있다
- 하트 / 자원 / 버프 UI가 한 프레임 늦게 보인다
- 팝업이나 시스템 메시지가 중복 출력된다
- 플로팅 텍스트 위치가 이상하거나 대상이 바뀐다
- 아이콘 드래그/등록 상태가 실제 데이터와 다르다

---

## 점검 순서

## 1. UI의 진짜 데이터 소스가 누구인지 먼저 확인합니다

UI 문제를 볼 때 가장 먼저 해야 할 질문은 이것입니다.

- 이 UI는 누구의 값을 표시하는가
- 직접 모델을 읽는가
- Presenter 나 Controller 를 거치는가
- 이벤트 기반인가, 폴링 기반인가

예를 들어 같은 HP UI라도
실제 데이터 소스가 `CharacterStat`인지, `PlayerUIController`인지, 별도 프레젠터인지에 따라
문제를 추적하는 출발점이 달라집니다.

---

## 2. 상태 변경은 되었는지, 표시만 안 된 것인지 구분합니다

겉으로는 모두 “UI 버그”처럼 보이지만,
실제로는 두 가지 경우가 있습니다.

- 런타임 상태 자체가 안 바뀜
- 상태는 바뀌었는데 UI 반영만 안 됨

따라서 반드시 다음을 분리해서 확인합니다.

- 모델 값 변경 여부
- 상태 변경 이벤트 발행 여부
- UI 수신 여부
- 실제 렌더링 갱신 여부

이 네 단계 중 어디서 끊기는지 찾는 것이 중요합니다.

---

## 3. 첫 sync 와 이후 sync 를 분리해서 봅니다

UI는 보통 두 종류의 동기화가 있습니다.

- 초기 표시를 위한 첫 sync
- 값 변경에 따른 이후 sync

자주 생기는 문제:
- 창을 열 때 첫 값은 잘못 보임
- 이후 변경은 정상 반영됨
- 또는 반대로 첫 값은 맞는데, 이후 이벤트를 못 받음

따라서 디버깅 시점도 아래처럼 나눠서 보는 것이 좋습니다.

- 생성 직후 상태
- 바인딩 직후 상태
- 첫 갱신 직후 상태
- 실시간 변경 중 상태

---

## 4. 구독과 해제의 짝을 확인합니다

UI는 이벤트 구독 누락도 문제지만,
해제 누락도 매우 큰 문제를 만듭니다.

체크 항목:
- 창을 열 때 구독하는가
- 창을 닫을 때 해제하는가
- 대상 캐릭터가 교체되면 이전 구독을 해제하는가
- 풀링된 UI 요소가 이전 상태를 유지하지 않는가

이 문제가 있으면 다음 현상이 자주 나옵니다.
- 중복 이벤트 수신
- 닫은 창이 계속 갱신됨
- 이전 플레이어의 값이 새 UI에 섞임

---

## 5. 풀링/재사용 UI는 초기화 규칙을 따로 확인합니다

아이콘, 하트, 슬롯, 버프 리스트 같은 UI는
새로 만드는 것보다 풀링/재사용 구조를 쓰는 경우가 많습니다.

이럴 때는 다음을 봅니다.

- 재사용 전 Reset 이 충분한가
- 이전 아이콘/텍스트/색/상태 키가 남아 있지 않은가
- 개수 변화가 있을 때 비활성화 처리까지 끝나는가
- 데이터가 줄어든 경우 화면에서 제거되는가

UI 재사용 문제는 값 계산이 맞아도 화면이 틀리게 보이게 만듭니다.

---

## 6. 레이아웃 문제와 데이터 문제를 구분합니다

간혹 값은 맞지만 화면상만 틀리게 보이는 경우가 있습니다.

예시:
- 앵커/피벗 문제
- LayoutGroup 재빌드 타이밍 문제
- World Space UI 대상 추적 위치 문제
- 해상도 / SafeArea / Flip 대응 문제

따라서 수치가 맞는데 위치/순서/정렬만 이상하다면
데이터 동기화보다 레이아웃과 Transform 갱신 순서를 먼저 봐야 합니다.

---

## 7. 저장 복원 이후 UI 갱신 순서를 확인합니다

저장 데이터를 복원한 뒤 UI가 이전 값처럼 보이는 경우가 많습니다.
이 경우 보통 세 가지입니다.

- 복원은 됐는데 UI가 재동기화되지 않음
- UI가 먼저 생성되어 기본값을 표시하고 있음
- 복원 후 이벤트 발행이 생략됨

따라서 저장/로드 관련 UI 버그는
반드시 저장 복원 단계와 UI sync 단계를 나눠서 확인해야 합니다.

---

## 빠른 체크리스트

- 이 UI의 실제 데이터 소스가 명확한가
- 모델 값 변경과 표시 갱신을 구분해서 확인했는가
- 첫 sync 와 이후 sync 를 따로 확인했는가
- 구독/해제가 짝을 이루는가
- 풀링 UI 의 Reset 규칙이 충분한가
- 레이아웃 문제와 데이터 문제를 구분했는가
- 저장 복원 후 UI 재동기화 시점이 있는가

---

## 자주 생기는 문제

### 1. 값은 맞는데 화면만 이전 상태처럼 보임

재사용 UI Reset 누락이나 구독 누락 가능성이 큽니다.

### 2. 창을 다시 열면 두 번씩 반응함

닫을 때 이벤트 해제가 빠졌을 가능성이 높습니다.

### 3. 플레이어 교체 후 HUD가 이전 대상을 따라감

대상 바인딩 교체 시 이전 참조와 구독을 정리하지 않은 경우가 많습니다.

### 4. 저장 로드 직후 한 프레임 동안 틀린 값이 보임

UI 생성과 복원 적용 순서가 엇갈린 경우입니다.
첫 sync 타이밍을 별도로 점검하는 것이 좋습니다.

---

## 한 줄 정리

UI 동기화 문제는 “화면이 틀리다”보다 **데이터 변경, 이벤트 전달, 첫 sync, 재사용 초기화 중 어느 단계가 빠졌는가**를 찾는 방식으로 보는 것이 가장 효과적입니다.
