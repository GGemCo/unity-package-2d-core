# Addressables 점검 체크리스트

## 문서 목적

이 문서는 Core 패키지에서 **프리팹, 윈도우, VFX, 사운드, 설정 ScriptableObject, 런타임 자산**이
정상적으로 로드되지 않거나, 일부만 보이거나, 해제 타이밍이 꼬일 때 확인할 항목을 정리한 체크리스트입니다.

Core는 여러 시스템에서 Addressables를 사용해 공통 리소스를 로드합니다.
따라서 문제 증상은 UI, 전투, 로딩, VFX, 설정 로드 어디서든 나타날 수 있습니다.
겉으로는 시스템별 버그처럼 보여도, 실제 원인은 **Addressable 키/그룹/참조 카운트/초기화 순서**일 수 있습니다.

---

## 먼저 확인할 관련 클래스 / 폴더

- `AddressableLoader/AddressableLoaderController.cs`
- `AddressableLoader/AddressableLoaderSettings*.cs`
- `AddressableLoader/AddressableLoaderPrefab*.cs`
- `Configs/Addressables/*`
- 관련 ScriptableObject 설정
- 관련 Editor Addressables 세팅 툴

---

## 이런 증상에서 먼저 봅니다

- 특정 프리팹이 로드되지 않는다
- UI 창만 열리지 않는다
- VFX / 사운드 / Projectile 프리팹이 일부 환경에서만 누락된다
- 설정 ScriptableObject가 기본값처럼 동작한다
- 처음 한 번은 되는데 씬 재진입 후 실패한다
- 메모리 해제가 안 되거나 오히려 너무 빨리 사라진다

---

## 점검 순서

## 1. Addressable 키가 실제 설정과 일치하는지 확인합니다

가장 먼저 확인해야 하는 항목은 문자열 키입니다.

체크 항목:
- 하드코딩 문자열과 Config 상수가 일치하는가
- 런타임이 기대하는 키와 Addressables 등록 키가 같은가
- 패키지별 prefix / naming 규칙이 섞이지 않았는가

가장 흔한 실수는 코드 수정 후 에디터 설정이 따라오지 않은 경우입니다.

---

## 2. 로드 대상이 정말 Addressables 그룹에 포함되어 있는지 확인합니다

키가 맞아도 실제 그룹에 없으면 로드되지 않습니다.

특히 다음을 함께 봅니다.
- 대상 에셋이 Addressable 체크되어 있는가
- 올바른 그룹에 들어 있는가
- 라벨이나 하위 에셋 구조가 기대와 일치하는가
- ScriptableObject, 하위 프리팹, 서브 에셋이 누락되지 않았는가

---

## 3. “로딩 실패”와 “로드는 됐지만 사용 실패”를 분리합니다

겉으로는 같은 현상처럼 보이지만 전혀 다른 문제일 수 있습니다.

예시:
- 로드는 성공했지만 타입 캐스팅이 잘못됨
- 로드는 성공했지만 초기화 코드를 안 탐
- 프리팹은 받았지만 씬에 Instantiate 되지 않음
- 설정 SO는 받았지만 참조하는 곳이 이전 캐시를 들고 있음

따라서 로그를 다음 두 단계로 나누는 것이 좋습니다.

- Addressables 로드 성공 여부
- 로드된 결과 사용 성공 여부

---

## 4. 초기화 타이밍을 함께 확인합니다

Addressables 문제는 종종 키 문제가 아니라 “너무 일찍 요청함” 문제입니다.

예시:
- Addressables 시스템 초기화 전 요청
- Settings 로드 전, 그 Settings 를 참조하는 시스템이 먼저 실행
- 로딩 씬 전용 자산이 아직 준비되지 않았는데 게임 씬 로직이 먼저 접근

이 경우는 로드 코드 자체는 맞아도, 시점 때문에 실패합니다.

---

## 5. 캐시 전략이 있는지 확인합니다

Core 구조에서는 반복 로드 비용을 줄이기 위해
Addressable 로더 계층이나 매니저 계층에서 캐시를 둘 수 있습니다.

이럴 때는 다음을 확인합니다.

- 같은 키를 매번 새로 로드하는가
- 이미 로드한 핸들을 재사용하는가
- 씬 전환 후 캐시를 유지해야 하는가
- 캐시 무효화 시점이 적절한가

문제 유형:
- 이전 씬의 캐시를 재사용해서 잘못된 상태를 들고 있음
- 캐시를 지워야 하는데 안 지움
- 캐시를 유지해야 하는데 너무 빨리 해제함

---

## 6. 참조 카운트와 릴리즈 타이밍을 추적합니다

Addressables에서 자주 생기는 문제는 “로드가 안 됨”보다도
**언제 해제했는지 모르는 상태**입니다.

체크 항목:
- 로드와 릴리즈가 짝을 이루는가
- Instantiate 한 오브젝트와 핸들 해제가 맞물리는가
- One-shot 과 지속형 리소스가 같은 규칙으로 관리되고 있지 않은가
- 패키지 종료 / 씬 종료 시점에 어떤 자산을 정리하는가

특히 VFX, UI 윈도우, 지속형 프리팹은
너무 이른 릴리즈가 눈에 잘 띄지 않게 문제를 만듭니다.

---

## 7. ScriptableObject 설정 자산은 “존재 여부”와 “적용 여부”를 함께 봅니다

설정 SO는 로드만 성공해도 문제 없어 보이기 쉽습니다.
하지만 실제 문제는 그 뒤에 있습니다.

체크 항목:
- 올바른 설정 에셋을 로드했는가
- 동일 타입의 다른 에셋이 섞이지 않았는가
- 로드된 값을 실제 시스템이 다시 읽고 있는가
- 런타임 중 변경 시 반영 이벤트가 필요한가

즉, 설정 자산은 “받아왔다”에서 끝내지 말고
“누가 이 값을 쓰는가”까지 확인해야 합니다.

---

## 빠른 체크리스트

- Addressable 키가 Config 와 실제 등록 상태와 일치하는가
- 대상 에셋이 올바른 그룹/라벨/하위 자산 구조로 등록되어 있는가
- 로드 실패와 사용 실패를 구분해서 로그를 보고 있는가
- 너무 이른 시점에 로드 요청을 보내고 있지 않은가
- 캐시 정책과 씬 전환 정책이 명확한가
- 로드/릴리즈가 짝을 이루는가
- 설정 SO는 로드 이후 실제 사용까지 확인했는가

---

## 자주 생기는 문제

### 1. 에디터에서는 되는데 빌드에서만 안 됨

대부분 Addressables 등록 누락, 그룹 설정 누락, 직접 에셋 참조와 Addressables 참조 혼용 문제가 많습니다.

### 2. 첫 진입만 성공하고 두 번째부터 실패

캐시나 릴리즈 타이밍을 의심하는 것이 좋습니다.
특히 씬 전환 후 핸들이 살아 있는지 확인해야 합니다.

### 3. 설정 파일을 바꿨는데 값이 그대로임

이전 캐시를 쓰고 있거나, 로드 후 값을 다시 소비하지 않는 구조일 수 있습니다.

### 4. VFX / UI가 잠깐 보였다가 사라짐

프리팹 문제보다 릴리즈 타이밍 문제인 경우가 많습니다.
Instantiate 생명주기와 핸들 해제를 함께 봐야 합니다.

---

## 한 줄 정리

Addressables 디버깅은 “로드가 안 된다”보다 **키, 등록, 시점, 캐시, 릴리즈 중 어느 축이 어긋났는지**를 구분해서 보는 것이 핵심입니다.
