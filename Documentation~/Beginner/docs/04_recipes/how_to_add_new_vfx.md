# 새 VFX 추가하기

## 문서 목적

이 문서는 Core 패키지의 VFX 시스템에 **새로운 시각 효과를 추가하거나 기존 재생 규칙을 확장**할 때,
어떤 순서로 리소스와 코드를 연결하면 좋은지 정리한 레시피입니다.

현재 Core의 VFX는 단순 프리팹 재생을 넘어서,
Addressables 로딩, 재생 정책, follow 여부, 정리 시점, 캐릭터/스킬/상태 이상 연결을 함께 다룹니다.
따라서 새 VFX는 **리소스 등록 → 식별 키 정리 → 호출 규칙 정의 → 런타임 재생 연결 → 종료 정책 검증** 순서로 접근하는 편이 안전합니다.

---

## 먼저 확인할 관련 클래스 / 폴더

- `Vfx/VfxManager.cs`
- `Vfx/VfxBehaviourBase.cs`
- `Vfx/VfxFadeController.cs`
- `AddressableLoader/AddressableLoaderPrefabVfx.cs`
- `Configs/Addressables/ConfigAddressable*`
- 호출부에 따라 `AnimationEventMediator`, Projectile, Affect 브리지 계층

---

## 언제 이 레시피를 사용하나요?

- 새로운 히트 이펙트, 버프 이펙트, 지속형 이펙트를 추가하고 싶을 때
- 특정 캐릭터 부위나 위치에 붙는 효과가 필요할 때
- one-shot, follow, duration override 같은 재생 정책을 확장하고 싶을 때

---

## 권장 구현 순서

## 1. VFX를 “효과 자산”과 “재생 규칙”으로 분리해서 생각합니다

새 이펙트를 추가할 때 가장 먼저 해야 할 일은,
파티클이나 프리팹 자체와 재생 규칙을 분리하는 것입니다.

예를 들어,
- 어디에 붙는가
- 누구를 따라가는가
- 자동으로 꺼지는가
- 수동 정지가 필요한가
- 동시에 여러 개 켤 수 있는가

이런 정보는 프리팹 자체보다 런타임 재생 규칙에 속합니다.

---

## 2. 리소스 키와 Addressables 등록 방식을 먼저 정리합니다

새 VFX는 런타임에서 일관된 키로 찾을 수 있어야 합니다.
따라서 아래를 먼저 맞추는 것이 좋습니다.

- Addressables 키 규칙
- 그룹/라벨/경로 규칙
- 관련 Config 상수 추가
- 로더가 해당 키를 안정적으로 찾을 수 있는지 여부

중요한 점은, 호출부가 프리팹 경로를 직접 문자열로 들고 있지 않게 만드는 것입니다.

---

## 3. 프리팹은 “보여주는 역할”에 집중시킵니다

VFX 프리팹은 다음 정도 책임으로 유지하는 것이 좋습니다.

- 파티클 시스템 / 스프라이트 / 셰이더 표현
- 기본 재생 길이
- 루프 여부
- 필요한 경우 페이드/종료용 보조 컴포넌트

게임 로직은 프리팹에 넣지 않습니다.
특히 “누가 맞았을 때 무엇이 적용되는지” 같은 전투 의미는 VFX 쪽이 아니라 호출부에 있어야 합니다.

---

## 4. 재생은 `VfxManager` 기준으로 통일합니다

새 효과를 재생할 때는 가능하면 `VfxManager`를 공통 진입점으로 사용하는 것이 좋습니다.

이유:
- 생성과 정리 경로가 한 곳으로 모임
- 나중에 풀링, 프리웜, 추적 로직 확장 시 유리함
- 디버깅 시 어느 시스템이 이펙트를 만들었는지 추적 쉬움

특히 캐릭터, Projectile, Affect, AnimationEvent가 각각 따로 Instantiate하는 구조는 피하는 편이 좋습니다.

---

## 5. one-shot / follow / loop를 구분합니다

새 VFX를 추가할 때 가장 먼저 정해야 하는 실행 규칙입니다.

- **one-shot**: 한 번 재생 후 자동 종료
- **follow**: 대상 Transform을 따라감
- **loop**: 외부에서 끌 때까지 유지

이 구분이 명확하지 않으면,
지속형 이펙트가 one-shot처럼 바로 사라지거나,
one-shot 이펙트가 씬에 남아 누적되는 문제가 생깁니다.

---

## 6. 위치 기준을 명확히 합니다

VFX 시스템에서 자주 문제가 나는 부분은 재생 위치입니다.

예를 들어 다음 기준을 구분해야 합니다.

- 월드 좌표 기준
- 캐스터 기준
- 타겟 기준
- 머리 위치 / 발 위치 / 중심점 기준
- 오프셋 적용 여부

현재 프로젝트는 캐릭터, Affect, Projectile, Cutscene 등 여러 시스템이 VFX를 사용하므로,
위치 기준을 문서화하고 재사용 가능한 helper 또는 policy로 두는 편이 좋습니다.

---

## 7. 정지/해제 정책을 설계합니다

loop 또는 follow 이펙트는 “언제 정지되는가”가 더 중요합니다.

체크 항목:
- owner가 파괴될 때 자동 정리되는가
- 상태 해제 시 꺼지는가
- 스킬 종료 시 정리되는가
- 중복 재생 시 교체/누적/무시 중 어떤 정책인가

지속형 VFX는 재생보다 정리 로직이 더 중요하다고 봐도 됩니다.

---

## 8. 호출 시스템별 책임을 분리합니다

새 VFX는 여러 시스템에서 쓸 수 있습니다.

권장 책임 분리:
- Skill/Affect/Projectile/AnimationEvent: “언제 어떤 VFX를 요청할지” 결정
- Core VFX: “어떻게 재생하고 정리할지” 처리

즉, 상위 시스템은 의미를 알고,
Core는 재생 인프라를 제공하는 구조가 좋습니다.

---

## 추천 구현 체크리스트

- VFX 키와 Addressables 등록 규칙이 정리되었는가
- 호출부가 프리팹 경로를 직접 알지 않는가
- one-shot / follow / loop 구분이 명확한가
- 위치 기준과 오프셋이 정의되어 있는가
- 정지/정리 정책이 있는가
- 중복 재생 정책이 있는가
- 게임 규칙과 연출 재생 책임이 분리되어 있는가

---

## 자주 생기는 문제

### 1. 이펙트가 남아 사라지지 않음

지속형 VFX 정리 토큰이나 owner 수명 연동이 부족할 때 생깁니다.
loop 계열은 항상 정지 조건을 먼저 만들어야 합니다.

### 2. 캐릭터를 따라가지 않음

follow 설정이 빠졌거나, 월드 좌표 기반으로만 생성된 경우입니다.
Transform 추적 정책을 따로 확인해야 합니다.

### 3. 재생은 되는데 위치가 이상함

pivot, anchor point, sprite bounds, 캐릭터 기준점이 맞지 않는 경우가 많습니다.
특히 머리 위치처럼 의미 있는 기준점은 helper로 통일하는 편이 좋습니다.

### 4. Skill/Affect가 VFX 구현 세부를 너무 많이 앎

상위 시스템이 VFX 경로, 수명, follow 구현까지 알게 되면 결합도가 급격히 높아집니다.
키와 요청 파라미터까지만 알고, 실행은 Core가 맡는 편이 좋습니다.

---

## 한 줄 정리

새 VFX를 추가할 때는 **파티클 프리팹을 하나 넣는 작업**이 아니라,
**Core의 공용 연출 시스템 안에 재생 규칙과 정리 규칙을 함께 등록하는 작업**으로 보는 것이 좋습니다.
